# Session — Fonctionnalité Zones routières (Z1 / Z2 / Z3)

## Contexte

Ajout d'une classification « zone routière » pour chaque voiture, afin de restreindre les itinéraires selon le type de routes acceptées par le véhicule (goudron / pavé / tout-terrain). À Madagascar, de nombreuses voitures bas-de-caisse ne peuvent pas rouler sur latérite ou piste.

### Classification retenue

| Zone | Surfaces OSM | Description |
|------|--------------|-------------|
| Zone 1 | `asphalt`, `paved`, `concrete` | Goudron uniquement |
| Zone 2 | Z1 + `paving_stones`, `sett`, `cobblestone` | Goudron + pavé |
| Zone 3 | Toutes surfaces (sauf `mud`) | Tout-terrain |

### Migration
- `alembic/versions/e5f6a7b8c9d0_add_zone_routiere_voiture.py` — ajoute la colonne + index

### Incohérence Alembic détectée et résolue
L'historique Alembic avait **2 branches parallèles** non fusionnées :
- Branche A : `b1c2d3e4f5a6 → d4e5f6a7b8c9 (heure_dispo)` — migration jamais trackée en DB mais schéma présent
- Branche B : `88563fdeac78 → 8b70a50dba4b (fix analytics FK cascade)` — seule tracée en `alembic_version`

**Procédure de résolution** :
1. `INSERT INTO alembic_version (version_num) VALUES ('d4e5f6a7b8c9')` — rattrape la trace manquante
2. `alembic merge heads` → crée `2db752798e31_merge_heads_zone_routiere.py`
3. Comme `upgrade head` refusait (overlap), application manuelle :
   - `ALTER TABLE voitures ADD COLUMN zone_routiere VARCHAR(10) NOT NULL DEFAULT 'zone3'`
   - `CREATE INDEX ix_voitures_zone_routiere ON voitures(zone_routiere)`
   - `DELETE FROM alembic_version WHERE version_num='d4e5f6a7b8c9'`
4. `alembic stamp 2db752798e31` → consolide en une seule head propre

Toutes les voitures existantes passent en `zone3` (comportement rétrocompatible).

## Étape 2 — Profils OSRM par zone

### Fichiers créés
- `osrm-data/profiles/car-zone1.lua` — wrap du `car.lua` standard, accepte `asphalt`/`paved`/`concrete` + autoroutes/primaires/secondaires sans tag surface
- `osrm-data/profiles/car-zone2.lua` — ajoute `paving_stones`/`sett`/`cobblestone` + tertiaires
- `osrm-data/profiles/car-zone3.lua` — bloque uniquement `surface=mud`
- `scripts/build_osrm_zones.sh` (exécutable) — pour chaque zone : `osrm-extract` → `osrm-partition` → `osrm-customize` via image Docker `osrm/osrm-backend:latest`

### Fichier modifié
- `docker-compose.yml` — 3 services `osrm-zone1/2/3` sur ports **5001 / 5002 / 5003**

### Opérations shell exécutées
- `./scripts/build_osrm_zones.sh` → préprocesse les 3 graphes dans `osrm-data/zone{1,2,3}/`
- `docker compose up -d osrm-zone1 osrm-zone2 osrm-zone3`
- Suppression de l'ancien conteneur `osrm-madagascar` devenu redondant avec `tml-osrm-zone3`

### Validation
Test OSRM `curl` sur les 3 ports avec le même itinéraire (centre Antananarivo → Ivato) :
- Zone 2 : snap 247 m / 418 m, distance 12.4 km
- Zone 3 : snap 7 m / 268 m, distance 13.5 km

Comportement attendu : zone 3 trouve une route proche mais plus longue (inclut les pistes), zone 2 force à rejoindre une route pavée plus éloignée.

## Étape 3 — Backend : routage dynamique selon la zone

### Fichiers modifiés
- `app/client/itineraire/external.py`
  - Mapping `OSRM_PORTS = {"zone1": 5001, "zone2": 5002, "zone3": 5003}`
  - `appeler_osrm(waypoints, client, zone)` route vers le bon port
  - Extraction des `snapped_waypoints` depuis la réponse OSRM : `lat`, `lon`, `walk_m`, `name`

- `app/client/itineraire/service.py`
  - `calculer_itineraire(waypoints, zone)` — normalise la zone et la propage
  - `_fallback_haversine(waypoints, zone)` — enrichi avec `snapped_waypoints` et `zone_routiere`
  - `emettre_token(..., zone_routiere)` — inclut la zone dans le JWT signé

- `app/client/itineraire/routes.py`
  - Charge la voiture via `voitures_service.get_voiture_by_id`
  - Lit `voiture.zone_routiere`, la passe au service
  - Renvoie `zone_routiere` et `snapped_waypoints` dans le JSON de réponse

- `app/client/reservations/service.py`
  - Vérifie que `token.zone_routiere == voiture.zone_routiere` avant d'accepter le devis (anti-tampering)
  - Tolère les anciens tokens sans zone (rétrocompat)

## Architecture finale

```
Client (template étape 1) ──► bandeau zone + warnings snap
        │
        ▼
Frontend JS (routing.js) ──POST──► /api/voitures/{id}/itineraire/calculer
                                            │
                                            ├─ Charge voiture (BD)
                                            ├─ Lit zone_routiere
                                            │
                                            ▼
                                   appeler_osrm(zone)
                                            │
                        ┌───────────────────┼───────────────────┐
                        ▼                   ▼                   ▼
                  tml-osrm-zone1      tml-osrm-zone2      tml-osrm-zone3
                  (port 5001)         (port 5002)         (port 5003)
                  profil Lua Z1       profil Lua Z2       profil Lua Z3
                        │                   │                   │
                        └───────────────────┼───────────────────┘
                                            ▼
                        Retour : distance_km + polyline + snapped_waypoints
                                            │
                        JWT signé (voiture_id + zone_routiere + distance)
                                            │
                                            ▼
                        Réservation : vérif token.zone == voiture.zone
```
